# 本地开发环境

> 状态：占位文档。当前仓库尚未形成可运行的前后端工程，因此本文不提供未经验证的版本号和命令。完成工程初始化后，提交者应在支持的操作系统上逐步验证并更新本文。

## 用途

本文帮助新成员在自己的电脑上搭建 LostLink 开发环境。团队协作、Issue、分支和 Pull Request 流程见 [development.md](development.md) 与 [CONTRIBUTING.md](../CONTRIBUTING.md)；测试和部署要求分别见 [testing.md](testing.md) 与 [deploy.md](deploy.md)。

## 前置条件

工程初始化后补充下表。版本应与项目配置和持续集成保持一致，不只写“最新版”。

| 工具或服务 | 支持版本 | 用途 | 状态 |
| --- | --- | --- | --- |
| Git | 待确认 | 获取代码和版本管理 | 待补充 |
| Python | 待确认 | 运行 FastAPI 后端 | 待后端初始化 |
| Python 包管理器 | 待确认 | 安装和锁定后端依赖 | 待后端初始化 |
| Node.js | 待确认 | 运行 Vue 前端工具链 | 待前端初始化 |
| Node.js 包管理器 | 待确认 | 安装和锁定前端依赖 | 待前端初始化 |
| MySQL | 待确认 | 本地数据库 | 待数据库初始化 |
| Docker | 待确认是否必需 | 可选的依赖服务运行方式 | 待部署方案确认 |

选定版本后，应通过 `.python-version`、`.nvmrc` 或 `.tool-versions` 等文件固定运行时版本，并提交相应依赖锁文件。

## 1. 获取项目

补充经过验证的仓库克隆方式、默认分支以及进入项目目录的步骤。如果项目包含 Git submodule 或 Git LFS，也应在这里明确说明。

## 2. 配置环境变量

工程初始化后，在仓库中提供 `.env.example`：

1. 将 `.env.example` 复制为本地 `.env`。
2. 按注释填写本地开发值。
3. 不要把 `.env`、真实密钥、生产地址或生产数据提交到 Git。

每个变量应说明用途、是否必需、示例格式和获取方式。变量的真实值不得写入本文。

## 3. 启动本地依赖服务

补充 MySQL 以及未来可能使用的缓存、对象存储或消息队列的启动方式，并明确：

- 所需版本和默认端口
- 本地数据库名称及创建方式
- 初始化或测试数据的生成方式
- 服务健康检查方法
- 停止服务和清理本地数据的方法

如果采用 Docker Compose，应记录实际验证过的启动和停止命令，并说明哪些数据会被删除。

## 4. 配置并启动后端

后端工程初始化后，补充以下步骤及真实命令：

1. 创建或启用隔离的 Python 环境。
2. 安装锁定的依赖。
3. 检查环境变量和数据库连接。
4. 执行 Alembic migration。
5. 启动 FastAPI 开发服务器。
6. 访问健康检查和 OpenAPI 文档，确认服务可用。

后端依赖、目录和专项命令的详细说明维护在 [backend/README.md](../backend/README.md)。

## 5. 配置并启动前端

前端工程初始化后，补充以下步骤及真实命令：

1. 安装锁定的依赖。
2. 配置本地 API 地址。
3. 启动 Vue 开发服务器。
4. 在支持的浏览器中访问页面并确认 API 连接正常。

前端依赖、目录和专项命令的详细说明维护在 [frontend/README.md](../frontend/README.md)。

## 6. 运行检查和测试

补充与持续集成一致的命令，至少包括：

- 后端格式检查、静态检查和测试
- 前端格式检查、类型检查和测试
- OpenAPI 或接口契约检查
- 必要的端到端测试

测试范围和合并门槛见 [testing.md](testing.md)。

## 7. 验证安装成功

环境搭建完成后，新成员应能够独立完成：

- 前后端服务正常启动
- 健康检查返回成功
- 前端能够访问后端 API
- 数据库 migration 升级成功
- 最小测试集通过
- 停止并重新启动后，本地环境仍可正常使用

## 常见问题

工程初始化后，根据团队实际遇到的问题维护本节，例如：

- 端口被占用
- Python 或 Node.js 版本不兼容
- 依赖安装或锁文件校验失败
- MySQL 连接、字符集或权限错误
- migration 版本不一致
- 前端无法访问后端或浏览器跨域错误

每个问题应写明现象、检查方法和解决步骤，不只记录一条无法解释的命令。

## 文档维护要求

- 修改运行时版本、依赖管理方式、环境变量或启动命令时，同步更新本文。
- 文档中的命令必须在干净环境中验证。
- 不再适用的步骤直接删除，避免同时保留多套互相冲突的说明。
- 如果某一步只适用于特定操作系统，应明确标注适用范围并提供替代方式。
