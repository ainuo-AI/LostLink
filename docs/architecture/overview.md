# 系统架构总览

> 状态：认证、物品、图片、举报、匹配通知与管理控制台已完成 Vue、FastAPI 与 MySQL 联调。
>
> 最后核对：2026-10-06

本文描述 LostLink 的系统级边界、主要数据流和技术状态。前端与后端的内部模块分别见 [前端架构](frontend.md) 和 [后端架构](backend.md)，重要技术选择通过 [ADR](adr/README.md) 记录。

## 当前实现

仓库目前包含 Vue 3 前端，以及 FastAPI 的认证、物品、图片、举报、匹配通知和管理接口。前端使用受保护路由和当前标签页 Bearer 会话完成普通用户与管理员流程。

前端发布失物和登记拾物会写入后端，`localStorage` 仅保存未提交草稿，IndexedDB 暂存发布前图片。举报和匹配通知使用服务端数据，新记录发布后会触发可解释的规则匹配。

以下能力尚未实现：

- 校园统一身份验证、账号恢复和完整认领核验流程。
- AI、地图、对象存储、异步任务和站外通知集成。
- 组件及浏览器端自动化测试；MySQL 集成测试目前需要显式提供隔离数据库。
- 可部署的完整系统及其监控、备份和回滚能力。

预留目录只表达计划中的边界，不代表能力已经可用。

## 计划的系统结构

```text
浏览器
  ↓
Vue 3 前端
  ↓ HTTPS / JSON API
FastAPI 模块化单体
  ├─ 身份与权限
  ├─ 信息发布与搜索
  ├─ 匹配与反馈
  └─ 外部服务适配
  ↓
MySQL
```

浏览器不直接访问数据库或持有第三方服务密钥。AI、地图、对象存储和通知能力由后端统一适配，业务模块不依赖供应商私有字段。

## 业务边界

- **身份与权限**：识别用户、检查角色和资源归属，不承载匹配逻辑。
- **信息发布**：管理失物与拾物记录、图片和状态，不直接判定物品归属。
- **搜索与匹配**：检索记录并生成可解释的候选关系，只提供辅助建议。
- **认领与反馈**：记录候选确认、拒绝和关闭结果，为策略评估提供输入。
- **外部集成**：隔离 AI、地图、对象存储和通知供应商及其失败模式。

## 主要数据流

以下是当前已实现的主要服务端数据流：

1. 用户通过前端提交失物或拾物信息。
2. API 执行身份、权限和参数校验。
3. Service 编排业务规则，通过 Repository 持久化数据。
4. Matching 根据已确认的数据生成候选及可解释的评分信息。
5. 用户反馈候选结果，Calibration 使用反馈评估或调整后续策略。
6. 需要外部能力时，由 Integration 调用供应商并统一处理超时、失败和降级。

认领核验与外部集成仍属于后续范围；详见 [核心用户流程](../product/user-flows.md)。

## 跨端契约

- 请求、响应、错误结构和兼容性以 [API 文档](../api/README.md) 及未来生成的 OpenAPI 为准。
- 数据库字段不直接等于公开 API 字段。
- 前端不维护独立于 OpenAPI 的第二套接口事实来源。
- 权限由后端执行；前端只负责交互提示和入口控制。
- 接口、数据库和用户行为变化应在同一个 Pull Request 中同步代码、测试和文档。

## 技术状态

| 范围 | 当前选择 | 状态 |
| --- | --- | --- |
| 前端 | Vue 3、TypeScript、Vue Router、Vite | 普通用户和管理员页面均已接入真实接口 |
| 后端 | Python 3.12、FastAPI | 认证、物品、图片、举报、匹配和管理闭环已实现 |
| 数据库 | MySQL 8.4、SQLAlchemy | 用户、物品、图片、举报、通知、审计和校准模型已实现 |
| 数据迁移 | Alembic | 四份 migration 已完成本地 MySQL 升级验证；完整回滚需使用一次性数据库 |
| API 契约 | FastAPI 生成 OpenAPI | 已包含普通用户和管理员全部当前接口 |
| 部署平台 | 未选择 | 待确认 |

采用某项技术不等于默认引入其全部生态。ORM、认证、状态管理、组件库、任务队列和部署平台应在出现真实需求时单独评估。
