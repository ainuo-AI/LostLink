# 系统架构总览

> 状态：Vue、FastAPI、SQLAlchemy 和 MySQL 只读数据链路已验证；发布、举报和匹配通知仅在前端本地演示，外部服务仍为计划。
>
> 最后核对：2026-10-02

本文描述 LostLink 的系统级边界、主要数据流和技术状态。前端与后端的内部模块分别见 [前端架构](frontend.md) 和 [后端架构](backend.md)，重要技术选择通过 [ADR](adr/README.md) 记录。

## 当前实现

仓库目前包含 Vue 3 前端、FastAPI 健康检查和只读物品列表接口。前端通过接口层调用 `GET /api/v1/items`，后端再通过 SQLAlchemy Repository 查询 MySQL；首页搜索、筛选和分页使用这条真实链路。独立物品详情页通过首页缓存或现有列表接口查找记录，没有新增详情 API。

发布失物、登记拾物、举报和匹配通知走另一条独立的浏览器本地演示路径：`localStorage` 保存草稿、演示记录和通知状态，IndexedDB 保存用户所选图片。预置匹配通知与新发布的本地记录没有自动关联；它们不写入 MySQL，也不代表后端能力。

以下能力尚未实现：

- 身份认证以及发布、修改、举报处理、匹配反馈和关闭接口。
- 真实信息发布、服务端图片上传、通知发送和状态闭环。
- 服务端候选匹配、反馈校准及 AI、地图、对象存储和通知集成。
- 组件及浏览器端自动化测试；MySQL 集成测试目前需要显式提供隔离数据库。
- 可部署的完整系统及其监控、备份和回滚能力。

预留目录只表达计划中的边界，不代表能力已经可用。

## 计划的系统结构

```text
浏览器
  ↓
Vue 3 前端
  ↓ HTTPS / JSON API
FastAPI 模块化单体
  ├─ 身份与权限
  ├─ 信息发布与搜索
  ├─ 匹配与反馈
  └─ 外部服务适配
  ↓
MySQL
```

浏览器不直接访问数据库或持有第三方服务密钥。AI、地图、对象存储和通知能力由后端统一适配，业务模块不依赖供应商私有字段。

## 业务边界

- **身份与权限**：识别用户、检查角色和资源归属，不承载匹配逻辑。
- **信息发布**：管理失物与拾物记录、图片和状态，不直接判定物品归属。
- **搜索与匹配**：检索记录并生成可解释的候选关系，只提供辅助建议。
- **认领与反馈**：记录候选确认、拒绝和关闭结果，为策略评估提供输入。
- **外部集成**：隔离 AI、地图、对象存储和通知供应商及其失败模式。

## 主要数据流

以下是计划中的服务端完整流程，不是当前本地演示的数据流：

1. 用户通过前端提交失物或拾物信息。
2. API 执行身份、权限和参数校验。
3. Service 编排业务规则，通过 Repository 持久化数据。
4. Matching 根据已确认的数据生成候选及可解释的评分信息。
5. 用户反馈候选结果，Calibration 使用反馈评估或调整后续策略。
6. 需要外部能力时，由 Integration 调用供应商并统一处理超时、失败和降级。

计划流程不代表已经实现；已验证与计划中的用户流程见 [核心用户流程](../product/user-flows.md)。

## 跨端契约

- 请求、响应、错误结构和兼容性以 [API 文档](../api/README.md) 及未来生成的 OpenAPI 为准。
- 数据库字段不直接等于公开 API 字段。
- 前端不维护独立于 OpenAPI 的第二套接口事实来源。
- 权限由后端执行；前端只负责交互提示和入口控制。
- 接口、数据库和用户行为变化应在同一个 Pull Request 中同步代码、测试和文档。

## 技术状态

| 范围 | 当前选择 | 状态 |
| --- | --- | --- |
| 前端 | Vue 3、TypeScript、Vue Router、Vite | 首页真实只读查询、独立详情与举报页、本地发布和匹配通知演示已实现 |
| 后端 | Python 3.12、FastAPI | 基础应用和只读列表接口已实现 |
| 数据库 | MySQL 8.4、SQLAlchemy | 首个 items 模型和查询已验证 |
| 数据迁移 | Alembic | 初始升级、回滚和重新升级已验证 |
| API 契约 | FastAPI 生成 OpenAPI | 仅 `GET /api/v1/items` 等现有只读接口；本地演示没有服务端契约 |
| 部署平台 | 未选择 | 待确认 |

采用某项技术不等于默认引入其全部生态。ORM、认证、状态管理、组件库、任务队列和部署平台应在出现真实需求时单独评估。
