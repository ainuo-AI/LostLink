# 系统架构总览

> 状态：前端首页原型已验证；后端、数据库和外部服务仍为计划。
>
> 最后核对：2026-09-26

本文描述 LostLink 的系统级边界、主要数据流和技术状态。前端与后端的内部模块分别见 [前端架构](frontend.md) 和 [后端架构](backend.md)，重要技术选择通过 [ADR](adr/README.md) 记录。

## 当前实现

仓库目前只有可独立运行的 Vue 3、TypeScript 和 Vite 前端首页原型。页面数据来自 `HomeView.vue` 中的虚构数组，搜索和筛选全部在浏览器中完成。

以下能力尚未实现：

- FastAPI 应用、HTTP API 和身份认证。
- MySQL 数据库、数据模型和 Alembic migration。
- 真实信息发布、编辑、搜索和状态闭环。
- 候选匹配、反馈校准及 AI、地图、存储和通知集成。
- 前端单元测试、后端测试和端到端测试。
- 可部署的完整系统及其监控、备份和回滚能力。

预留目录只表达计划中的边界，不代表能力已经可用。

## 计划的系统结构

```text
浏览器
  ↓
Vue 3 前端
  ↓ HTTPS / JSON API
FastAPI 模块化单体
  ├─ 身份与权限
  ├─ 信息发布与搜索
  ├─ 匹配与反馈
  └─ 外部服务适配
  ↓
MySQL
```

浏览器不直接访问数据库或持有第三方服务密钥。AI、地图、对象存储和通知能力由后端统一适配，业务模块不依赖供应商私有字段。

## 业务边界

- **身份与权限**：识别用户、检查角色和资源归属，不承载匹配逻辑。
- **信息发布**：管理失物与拾物记录、图片和状态，不直接判定物品归属。
- **搜索与匹配**：检索记录并生成可解释的候选关系，只提供辅助建议。
- **认领与反馈**：记录候选确认、拒绝和关闭结果，为策略评估提供输入。
- **外部集成**：隔离 AI、地图、对象存储和通知供应商及其失败模式。

## 主要数据流

1. 用户通过前端提交失物或拾物信息。
2. API 执行身份、权限和参数校验。
3. Service 编排业务规则，通过 Repository 持久化数据。
4. Matching 根据已确认的数据生成候选及可解释的评分信息。
5. 用户反馈候选结果，Calibration 使用反馈评估或调整后续策略。
6. 需要外部能力时，由 Integration 调用供应商并统一处理超时、失败和降级。

计划流程不代表已经实现；已验证与计划中的用户流程见 [核心用户流程](../product/user-flows.md)。

## 跨端契约

- 请求、响应、错误结构和兼容性以 [API 文档](../api/README.md) 及未来生成的 OpenAPI 为准。
- 数据库字段不直接等于公开 API 字段。
- 前端不维护独立于 OpenAPI 的第二套接口事实来源。
- 权限由后端执行；前端只负责交互提示和入口控制。
- 接口、数据库和用户行为变化应在同一个 Pull Request 中同步代码、测试和文档。

## 技术状态

| 范围 | 当前选择 | 状态 |
| --- | --- | --- |
| 前端 | Vue 3、TypeScript、Vite | 首页原型已实现 |
| 后端 | FastAPI | 提议，尚未初始化 |
| 数据库 | MySQL | 提议，尚未初始化 |
| 数据迁移 | Alembic | 提议，尚未初始化 |
| API 契约 | FastAPI 生成 OpenAPI | 工作流已约定，尚无业务接口 |
| 部署平台 | 未选择 | 待确认 |

采用某项技术不等于默认引入其全部生态。ORM、认证、状态管理、组件库、任务队列和部署平台应在出现真实需求时单独评估。
