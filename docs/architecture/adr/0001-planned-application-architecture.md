# ADR-0001：采用前后端分离的单体应用作为初始架构

- 状态：提议
- 日期：2026-09-16
- 决策者：待团队评审

## 背景

LostLink 是软件工程课程项目，需要多人并行开发前端、接口、数据模型和匹配能力。本提议形成于 2026-09-16；当时只有可独立运行的前端首页原型，后端、数据库和真实接口尚未初始化。后来已实现只读列表链路，但部署方案仍未确定。此处保留提议时的背景，不把后续实现误写成当时已有能力。

初期需要控制运维复杂度，同时保持模块边界清晰，便于以后替换匹配算法或外部服务。

## 备选方案

1. **前后端分离的单体后端**：Vue 前端通过 HTTP API 访问 FastAPI，业务模块运行在同一个后端应用中。
2. **服务端渲染的单体应用**：部署简单，但与当前前后端分工和目录结构不一致。
3. **微服务**：隔离更强，但会提前引入服务治理、分布式事务、监控和部署成本。

## 决策

提议采用 Vue 3 前端、FastAPI 单体后端和 MySQL 数据库。后端内部按接口、业务服务、数据访问、匹配、校准和外部集成划分模块，但初期不拆成独立网络服务。

API 通过 OpenAPI 描述，数据库结构通过 Alembic migration 演进。具体依赖库、认证机制和部署平台不在本 ADR 中决定。

## 影响

- 前后端可以围绕稳定接口契约并行工作。
- 只有一个后端部署单元，适合项目当前规模。
- 模块边界依靠代码评审和测试维持，而不是进程隔离。
- 后端故障可能同时影响多个功能，需要统一的监控和降级策略。
- 若未来出现明确的独立扩缩容或团队边界，再通过新的 ADR 评估拆分服务。

## 验证条件

团队接受本提议前，应完成：

- 建立最小可运行的后端工程，并让现有前端通过真实 API 获取数据。
- 验证 OpenAPI 生成与前端调用流程。
- 验证 MySQL 连接和 Alembic 升降级流程。
- 确认团队成员可以在支持环境中完成本地开发。

截至 2026-10-02，前三项已有仓库实现及 2026-09-30 的本地验证记录；团队评审和成员环境确认没有可核实的结论，因此本 ADR 仍保持“提议”，不擅自改为“已接受”。
