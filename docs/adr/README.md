# Architecture Decision Records

ADR 用于记录重要、长期且难以从代码直接看出原因的技术决策。普通实现细节、容易撤销的选择或尚未形成方案的讨论不需要 ADR。

## 何时创建

- 选择或更换核心框架、数据库、认证方式或部署平台。
- 改变模块边界、依赖方向或关键数据流。
- 引入重要外部服务，尤其涉及个人数据或持续费用时。
- 作出难以回滚的数据兼容、安全或可用性选择。

## 文件命名

使用递增编号和简短标题：

```text
0001-use-vue-fastapi-and-mysql.md
0002-authentication-strategy.md
```

## 模板

```markdown
# ADR-NNNN：标题

- 状态：提议 / 已接受 / 已取代 / 已废弃
- 日期：YYYY-MM-DD
- 决策者：待填写

## 背景

需要解决什么问题，有哪些约束？

## 备选方案

考虑过哪些方案，各自主要利弊是什么？

## 决策

选择什么，适用边界是什么？

## 影响

带来哪些收益、成本、风险和后续工作？
```

已接受的 ADR 不直接改写结论。决策变化时创建新 ADR，并让新旧文件互相链接。
