# OpenAI 兼容图文匹配

> 实现日期：2026-10-07。已加入可选适配器、发布流程和模拟供应商测试；未使用真实密钥进行供应商联调。

## 配置

在 `backend/.env` 中设置以下变量，然后重启后端：

```dotenv
MATCHING_AI_ENABLED=true
MATCHING_AI_BASE_URL=https://api.deepseek.com
MATCHING_AI_API_KEY=填写自己的密钥
MATCHING_AI_MODEL=deepseek-flash
MATCHING_AI_TIMEOUT_SECONDS=10
MATCHING_AI_MAX_CANDIDATES=5
MATCHING_AI_WEIGHT=0.6
MATCHING_AI_MAX_IMAGE_BYTES=5242880
```

DeepSeek 官方当前图像指南使用 `deepseek-flash` 和上述 API 根地址。使用其他 OpenAI 兼容供应商时，填写其 API 根地址和支持图片输入的模型标识；兼容文本接口不代表模型支持图片。供应商也必须支持非流式 Chat Completions、`max_tokens` 和标准 `image_url` 内容块。

`BASE_URL` 可以带 `/v1`，不要带 `/chat/completions`，适配器会追加该路径。远程接口要求 HTTPS，本地 `localhost`、`127.0.0.1`、`::1` 服务允许 HTTP。API key 仅在服务端读取，不进入前端配置或接口响应；`.env` 已被 Git 忽略。开关默认关闭；启用时缺少地址、密钥或模型会导致配置校验失败。

参考：[DeepSeek 图像理解](https://api-docs.deepseek.com/zh-cn/guides/vision/)；[OpenAI Images and vision](https://developers.openai.com/api/docs/guides/images-vision)。

## 发布后的匹配流程

1. 保存物品、关联已经验证归属的图片。
2. 检索同校区、相反类型、进行中的记录，最多取最近 50 条。
3. 按规则分排序，把排名靠前的最多 5 条（可配置为 1～10）交给模型批量比较。规则中的地理分现使用[离线校园距离表](campus-distance-matching.md)。模型调用在最终 55 分阈值过滤之前执行，可提高规则低分候选的得分。
4. 请求包含源物品和候选的标题、描述、类别、校区、区域、地点、类型和发生时间。每条记录最多附一张可读的 JPG/PNG/WebP 图片，以 base64 传入，供应商无需访问本地上传 URL。总原始图片字节默认最多 5MB；超预算、丢失或不安全路径的图片跳过，以文字继续比较。
5. 严格验证返回的 JSON、候选集合、整数分数（0～100）及解释长度。默认综合分为 `规则分 × 0.4 + AI 分 × 0.6`，达到 55 分才生成去重通知；未进入 AI 批次的候选继续使用规则评分。
6. 成功使用模型的通知新增 `AI 图文` 解释维度，沿用现有通知和反馈接口。匹配分数是排序信号，不能解释为概率或物品归属确认。

不存在图片时调用模型比较文字。仅一方有图片时比较图片与另一方描述。模型提示明确要求时间和地点距离由本地规则计算，不得推测距离。模型不能保证识别同款物品的个体差异，需要人工核验。

## 失败与成本边界

- 每次发布至多一次外部请求，不自动重试，也不跟随重定向。
- HTTP 网络阶段超时默认 10 秒（这是 HTTPX 的阶段超时，并非整个发布操作的绝对时限）。错误、限流、缺少权限、不支持图片、无效 JSON 或候选集合不一致时，全部回退到现有规则，发布不因这些供应商错误而失败。
- 日志仅记录固定降级提示，不打印请求、响应、异常原文或密钥。
- 仅使用公开字段白名单，不发送独立的联系方式、所有者或关闭备注；用户描述和图片本身仍可能包含个人信息。启用前应落实供应商数据处理规则与产品告知。
- 第一版为发布流程内同步调用，没有任务队列、持久化重试、特征缓存或向量数据库。并发量提高后应移至独立 worker，并加入限流和任务状态。
- 仅新发布触发；不会重新计算已有通知，也不会因编辑图片或文本自动重算。同一对物品已有通知时沿用原通知。
- 当前校准版本还未控制这些模型参数；`MATCHING_AI_WEIGHT` 与原规则分的权重独立配置。

## 验证

在 `backend/` 执行 `uv run ruff check .` 和 `uv run pytest`。多模态测试通过 `httpx.MockTransport` 验证图片内容块、私密字段白名单、分数融合、候选数量、无效输出、网络异常、禁用开关和发布降级，不调用付费服务。

真实联调需要自己的模型权限和密钥：用两个测试账号发布同校区的失物与拾物，附上可解码的测试照片，然后查看通知中的 `AI 图文` 维度。若只有类别、时间、文本、地点四个规则维度，检查配置、供应商权限以及后端的固定降级提示。不存在符合条件的候选时不会调用模型。

本次沿用 `match_notifications` 的分数和解释 JSON 字段，不改变接口路径或数据库结构，无需新增 migration。
