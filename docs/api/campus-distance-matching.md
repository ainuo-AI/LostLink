# 离线校园距离匹配

2026-10-08：匹配规则已接入离线距离矩阵，前端沿用匹配详情的维度解释，不增加地图。
按用户要求，原有六个未能唯一定位的业务地点已填写虚构坐标，用于演示距离匹配。
涉及这六处的匹配说明明确标注“模拟”，不能解释为实地距离。

## 数据来源与当前覆盖

距离表位于 `backend/app/data/campus_distances.json`，收录 23 个条目：
15 个已在 OpenStreetMap 定位的建筑/入口、6 个模拟业务地点、2 个开发测试占位条目。
21 个有坐标地点之间有 210 对不同地点距离，其中 105 对仅涉及地图地点，
另 105 对涉及模拟地点。两个测试占位地点的距离项仍为 `null`。

公开地图数据由 OpenStreetMap 的 `/api/0.6/map` 导出接口于 2026-10-08 获取。
每个已定位条目保留原地图名称、对象链接和对象版本，便于复核。
出处：© [OpenStreetMap contributors](https://www.openstreetmap.org/copyright)，ODbL 1.0。

全表采用 **WGS84**，单位为米。地图建筑以轮廓的经纬度包围框中心为代表点，
地图校门使用节点；模拟地点采用手工填写的虚构经纬度。
基于这些坐标用球面距离公式离线计算并取整到米，匹配时只查本地表。
地图点之间是代表点的近似直线距离；涉及模拟点的距离仅为演示数值。
这些都不是步行路线、建筑入口到入口的距离或现场实测数据。
不混用高德 GCJ-02、百度 BD-09 或不同坐标系，不用校区中心代替建筑位置。

已定位点的例子：北教一与北教三约 50 米，北教一与北教二约 87 米，
北教一与明德馆约 1231 米。具体来源及全量矩阵均保存在 JSON 中。

## 地点选项

`GET /api/v1/locations` 无需登录，返回这 21 个有坐标的地点，字段为
`id`、`name`、`campus`、`area`、`simulated`。开发占位地点不作为用户选项。
发布失物、登记拾物和个人记录编辑中的地点均使用下拉框，不能自由填写。
发生地点按校区和区域筛选，切换后不适用的选择会清空；宁河校区不需要区域。
拾物保管地点可选择同校区任一区域的地点。

创建及编辑接口只接受目录中的标准 `name`，后端检查最终校区、区域与地点组合；
任意文本、别名、楼层后缀或范围错误返回 `422 / ITEM_LOCATION_INVALID`。
本机开发数据库的旧物品记录已按用户要求清空，不提供旧地点自动转换逻辑。
模拟地点在选项中有标识。

## 地点识别

距离解析先用校区和区域限定地点，再匹配名称/别名；新发布只提交标准名称。
支持空格、全角字符、楼层、三到四位房间号以及部分室内区域后缀；
例如“北教一二层”“北教1 302”“北教1号楼三层阅览区”归到北教1。
同一建筑的不同楼层按同一个代表点计算，显示代表点距离为 0 米，并明确室内位置未精细区分。

不能把“北教12”截断成“北教1”，也不会把“北教一到北教二”强行匹配到某一栋楼。
同校区同区域里有多个名称命中时判定为不唯一；不同校区/区域的同名地点互不混用。

## 评分与通知

地点分采用距离衰减规则：

```text
地点分 = round(100 × 2 ^ (-距离米数 / 500))
距离 >= 3000 米时，地点分 = 0
规则总分 = round(35%类别 + 20%时间 + 10%文本 + 35%地点)
```

| 距离 | 地点分 |
| --- | --- |
| 0 米 | 100 |
| 500 米 | 50 |
| 1000 米 | 25 |
| 2000 米 | 6 |
| 3000 米及以上 | 0 |

500 米与 3000 米是可调的排序参数，不是已经用标注数据校准的结论。
本次用距离替换原来的校区 20% 加区域 15%，保留其余规则权重。
没有改为之前举例的五维图文权重；现有可选 AI 分仍按 `MATCHING_AI_WEIGHT` 与规则总分融合。
地点缺少坐标时，维度返回 `score=null` 和原因，不给地点加分、不补“同校区满分”，
不重分配这 35% 权重，因此仅规则分的上限为 65。这会减少缺少地点证据的通知。

原来的同校区、相反类型、进行中记录预筛选保持不变；矩阵保留跨校区距离以避免同名混淆，
但跨校区记录当前不会进入候选查询。达到现有 55 分阈值才生成通知。
距离不会单独拒绝物品，也不能表示归属或找回概率。

通知维度变为“类别、时间、文本、地点”，前端已经支持动态维度和“未评估”。
地点解释显示建筑名称、约多少米、直线距离口径及模拟标识（如适用）。
模型提示要求图文模型比较物品特征，禁止推测距离。
已生成的通知保存原有评分快照，不会自动重算；新发布开始使用这套规则。

## 补齐与维护

1. 若要把模拟地点换成地图地点，先确认正式名称、坐标系和地图分享链接。
2. 将坐标统一到 WGS84，填写该条目的 `coordinates.latitude`、`coordinates.longitude`，
   补充真实 `source`，将 `status` 改为 `map_verified` 并移除模拟说明。
   继续使用虚构坐标时保持 `status=synthetic` 和 `source.kind=synthetic`。
3. 在 `backend/` 执行以下命令，自动重建该地点与所有其他地点的双向距离。
4. 检查改动后的矩阵并重启后端（表按进程缓存）。现有物品不需要数据库迁移。

```bash
.venv/bin/python -m scripts.build_campus_distances
.venv/bin/ruff check .
.venv/bin/pytest
```

测试覆盖全矩阵一致性、米制距离、别名和楼层、同名歧义、未知地点、不跨区域误识别、
距离影响排序、模拟点与地图点混合时的标识，以及实际发布通知中的距离解释。
运行时无需地图密钥或网络。
