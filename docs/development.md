# 开发流程

## 1. 需求确认

每个开发任务开始前应明确：

- 要解决的问题
- 输入和输出
- 涉及的角色与权限
- 正常流程和异常流程
- 可验证的验收条件

## 2. 接口先行

前后端共同确认接口路径、请求字段、响应字段、状态码和错误格式，再分别实现。

接口草案统一放入 `docs/api/`，未评审的草案不得视为稳定契约。

## 3. 小步实现

一次只完成一个可独立验证的模块。功能代码、测试和对应文档应在同一个 Pull Request 中交付。

## 4. 验证

提交前至少完成：

- 格式和静态检查
- 单元测试
- 接口或页面的关键路径检查
- 异常和边界场景检查
- 文档同步检查

## 5. 合并

Pull Request 通过评审和自动检查后再合并到 `main`。合并后删除已经完成的短期分支。
