# 安全说明

## 基本原则

- 默认只收集完成失物招领流程所需的数据。
- 默认拒绝未授权访问，服务端始终执行权限检查。
- 密钥、令牌、数据库密码和生产配置不进入 Git。
- 匹配结果只作为线索，不自动证明所有权。
- 外部服务只接收完成其任务所需的最少数据。

## 账号与权限

- 密码必须使用成熟算法安全哈希，不能明文保存或可逆加密。
- 登录、重置密码和敏感操作需要防止暴力尝试与账号枚举。
- 每个修改接口都要检查资源归属，不能只依赖前端隐藏按钮。
- 管理员权限与普通用户权限分离，高风险操作保留审计信息。

当前前端把 Bearer 令牌保存在当前标签页的 `sessionStorage`，关闭标签页或主动退出后清除，并在受保护页面首次导航时向服务端确认会话。该方式不把密码写入浏览器存储，但仍依赖前端避免 XSS；正式部署前应评审内容安全策略、令牌有效期和更安全的 Cookie 会话方案。

## 个人信息

失物招领内容可能包含姓名、联系方式、位置、行程和物品特征。设计与评审时应明确：

- 哪些字段公开，哪些只对相关用户显示。
- 联系方式在什么条件下展示。
- 精确地点是否需要模糊化。
- 信息关闭或账号注销后保存多久。
- 用户如何请求更正或删除自己的数据。

公开描述中应提醒用户不要填写证件号码、门禁信息、家庭住址等不必要的敏感内容。

当前前端会把尚未提交的表单草稿（包括原样联系方式）写入本机浏览器 `localStorage`，图片在发布前写入 IndexedDB；这些草稿在清理站点数据前仍留在该浏览器中，不适合在共享设备上填写真实联系方式。正式提交会把表单字段和图片发送到后端。正式发布前须重新评审联系方式与图片的可见范围、删除和保留期限。

后端物品发布接口已经保存完整联系方式，但只通过所有者或授权管理员响应返回；公开列表和详情仅含 `contact_hint`。数据库参数日志已隐藏，业务代码不得额外记录请求体或完整联系方式。联系方式加密、向其他用户受控展示及保留期限仍需产品和安全评审。

## 文件上传

服务端已支持 JPG、PNG、WebP，默认单张 5MB、每个物品最多 3 张。上传端同时检查声明的媒体类型、文件头和大小，以 UUID 生成存储键；临时图片只允许所有者删除，关联物品后才允许公开读取。仍需在生产部署前落实以下增强项：

- 将文件迁移到与应用执行环境隔离的对象存储，并设置不可执行响应头。
- 清理图片元数据，并评估病毒扫描和内容审核需求。
- 定义孤立临时图片的定期清理、关闭记录后的保留和用户删除策略。

## 日志与外部服务

可选图文匹配启用后会向配置供应商发送公开物品字段及选中的照片，使用字段白名单且不包含独立的完整联系方式、所有者编号和关闭备注。用户描述与图片可能自行包含个人信息，供应商保留规则及用户告知仍需确认；具体请求范围与降级策略见 [图文匹配接入说明](../api/multimodal-matching.md)。默认禁用，不打印请求、响应或供应商错误原文。

- 日志不记录密码、访问令牌、Cookie、完整联系方式或原始证件信息。
- 向 AI、地图和通知服务发送数据前，记录用途、字段、保存政策和失败处理。
- 外部请求设置超时、有限重试和降级策略。
- 开发和测试环境使用单独凭据，不复制生产个人数据。

## 依赖与配置

- 依赖版本锁定，并定期处理已知高风险漏洞。
- `.env.example` 只列变量名和非敏感示例。
- 密钥疑似泄露时立即轮换，仅从 Git 删除文件并不能消除历史泄露。
- 生产环境采用最小权限，并限制数据库和管理入口的网络访问。

## 漏洞报告

在仓库配置私密安全报告渠道前，不要创建包含漏洞利用细节、密钥或个人数据的公开 Issue。团队应尽快在 GitHub 启用 Private vulnerability reporting，并在此补充负责人和响应时限。

安全问题修复后，应增加回归测试；影响用户或数据时，还应记录事件时间线、影响范围和改进措施。
