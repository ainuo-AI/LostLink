## 测试目标

- 证明需求验收条件已经满足。
- 尽早发现业务规则、权限、接口契约和数据库变化中的回归。
- 让测试失败能够指出具体问题，而不是依赖一次性人工演示。

## 测试分层

| 层级 | 关注内容 | 建议位置 |

## 当前前端测试

在 `frontend/` 目录执行：

```powershell
npm.cmd test
npm.cmd run type-check
npm.cmd run build
```

Vitest 当前覆盖认证请求与 Bearer 请求头、物品查询/发布/个人列表/状态请求、FastAPI 错误转换、联系方式转换、时间显示、举报与匹配拒绝 API、草稿隔离、表单与图片规则。2026-10-10 的执行结果为 22/22 通过，类型检查和生产构建通过。类型检查与构建不能代替浏览器端端到端测试；Vue 组件交互、路由守卫、图片实际选择与预览尚未纳入自动化测试。

## 当前后端测试

在 `backend/` 目录执行：

```bash
uv run pytest
```

默认测试使用 FastAPI 测试客户端和内存仓储，不连接个人数据库，也不会调用真实外部服务。测试覆盖认证与权限、公开联系方式、物品边界、图片上传关联、举报审核、候选生成与拒绝反馈、用户限制和校准版本生命周期；确认匹配请求应返回 `422` 且候选保持原状态，拒绝原因缺失返回 `422`，重复拒绝返回 `409`。2026-10-10 为 95 个测试通过、3 个 MySQL 测试跳过。

设置 `TEST_DATABASE_URL` 后执行 `uv run pytest -m mysql`，可以在已迁移的隔离 MySQL 验证查询、用户会话以及物品写入与状态审计。2026-10-06 的 3 个 MySQL 集成测试通过记录为历史结果，不能代替最新代码的数据库联调。

Alembic migration 还需要在一次性数据库中验证 `upgrade head → downgrade base → upgrade head`。不得使用包含有效数据的共享数据库执行破坏性回滚测试。

## 当前交互的手工验收清单

以下是后续浏览器验收步骤，本轮尚未完整执行：

- 发布带照片的失物或拾物，在首页及个人记录卡片检查第一张照片缩略图，在详情检查按比例展示的照片与校区标签；无照片和图片请求失败时检查分类图标回退。
- 检查详情和匹配详情显示具体联系方式，联系说明单独展示；历史无联系方式记录显示“未提供联系方式”。
- 检查进行中、已找回、已归还和已关闭的失物及拾物详情均没有认领按钮，举报入口仍可进入。
- 登录后提交举报，确认成功页展示服务端编号与待处理状态；自举报或重复待处理举报显示后端错误。
- 打开匹配详情，检查已读同步、联系方式及解释分数；没有确认匹配按钮，未处理候选可填写原因拒绝，已拒绝记录不再显示操作表单。
- 若存在历史 `confirmed` 通知，检查仍可读取并显示为“已处理”；交接完成后由发布者在个人页标记找回或归还。

## 每个功能至少验证

- 一条正常路径。
- 必填项为空、格式错误和边界值。
- 未登录、无权限和资源不存在。
- 重复提交、依赖服务失败或超时。
- 与本次修改相关的历史行为没有回归。

涉及匹配策略时，使用固定数据集验证排序、阈值和解释字段，避免测试依赖实时外部 AI 输出。

## 测试数据

- 测试数据由 fixture 或工厂创建，不依赖个人本地数据库。
- 自动测试不得调用真实付费服务或向真实用户发送通知。
- 示例账号、图片和位置不得包含真实个人信息。
- 每个测试独立清理状态，不能依赖执行顺序。

## Pull Request 验证记录

作者应在 Pull Request 中写明：

- 执行过的自动检查及结果。
- 未执行的检查及原因。
- 需要评审者手工验证的步骤。
- 涉及界面时的关键状态截图或录屏。

## 合并门槛

- 与改动相关的自动测试通过。
- 新增业务规则具有对应测试。
- 修复缺陷时，优先增加能够复现该缺陷的回归测试。
- 暂时跳过的测试必须关联 Issue，并说明恢复条件。
- 不以降低断言质量或删除有效测试来换取通过。

覆盖率可用于发现测试空白，但不能单独代表质量。团队应在工程初始化和首批测试稳定后，再确定合理的覆盖率门槛。
